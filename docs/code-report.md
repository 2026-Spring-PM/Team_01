# 코드 보고서 (Code Report)

## a) 전체 모듈 구조
중앙 컨트롤러인 `Game` 클래스를 중심으로 객체지향적인 서브 시스템들이 결합된 아키텍처입니다.
* **코어 엔진**: `Game`(게임 루프), `Player`(플레이어 상태), `Map`(그리드 기반 맵), `GuiRenderer`(화면 렌더링)
* **농장 시스템**: `CropSystem`(작물 재배), `BarnSystem`(축사 관리), `LivestockSystem`(가축 관리)
* **상호작용 및 이벤트**: `EventSystem`(날씨 및 특수 이벤트), `MarketSystem`(경제 및 상점)

## b) 시스템 컴포넌트 구현
* **`Game`**: 핵심 클래스로 모든 서브 시스템 인스턴스를 보유하며, `handle_input()`으로 입력을 받아 각 시스템 객체에 명령을 전달합니다.
* **`Player` (상속 `GameObject`)**: 좌표, 재화, 스태미나, `Inventory`(인벤토리 객체), `LevelSystem`(경험치 객체) 등 플레이어 고유의 속성을 캡슐화하여 단일 객체로 관리합니다.
* **단일 책임 시스템 (`System` 클래스군)**: 
  * `CropSystem`: 정적(static) 메서드를 통해 `Tile` 객체의 상태를 직접 변경(씨앗 심기, 수분 상태 갱신)합니다.
  * `EventSystem`: 턴이 넘어갈 때 `process_new_day()`가 호출되며, 랜덤 이벤트를 계산해 `EventDayReport` 구조체로 UI 쪽에 반환합니다.

## c) C++ 주요 개념 적용
* **상속 및 다형성**: `GameObject` 기본 클래스를 상속받아 `Player` 클래스로 구체화했습니다.
* **캡슐화**: `Player`의 자원(돈, 스태미나)을 `private`으로 숨기고, `spend_money()` 등의 지정된 메서드로만 조작하도록 강제했습니다.
* **STL 컨테이너**: 인벤토리 및 이벤트 알림 관리에 `std::vector`와 `std::string`을 적극 활용했습니다.
* **메모리 관리**: 리소스나 렌더링 포인터 관리에 스마트 포인터(`std::unique_ptr`)를 사용하여 메모리 누수를 방지했습니다.

## d) 생성형 AI 활용 (※ 실제 내용으로 수정 필요)
* **활용 목적**: SDL2 GUI 라이브러리의 렌더링 초기 뼈대 코드 작성 및 `CropInfo` 같은 반복적인 데이터 세팅 작업에 활용했습니다.
* **코드 변경점**: `EventSystem`의 처리 로직과 팝업 출력 로직이 섞여 있던 코드를 분리하기 위해, AI가 제안한 `EventDayReport` 반환 구조체를 도입하여 코드 결합도를 낮췄습니다.
* **오류 해결**: AI가 생성한 렌더링 코드에서 프레임 저하와 메모리 누수 발생. 에러 로그를 분석하여 텍스처 해제(`SDL_DestroyTexture`) 코드가 누락된 것을 식별하고 직접 추가하여 수정했습니다.
